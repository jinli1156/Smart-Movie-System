# 影院权限与页面一致性

适用范围：根目录的 Spring Boot 后端、Vue 用户端及 Vue 管理端。独立的 `movie-ticket-unicloud` 项目已同步影院权限和页面调整，云端验证与部署状态见其 [README](../movie-ticket-unicloud/README.md)。两套服务的推荐算法不同，评估结果不能直接混用。

## 权限矩阵

| 操作 | 普通用户 USER | 影院管理员 CINEMA_ADMIN | 平台管理员 ADMIN |
| --- | --- | --- | --- |
| 本人订单列表 | 本人 | 本人 | 本人 |
| 订单详情、取消、退票、取票 | 本人订单 | 所属影院订单 | 全部订单 |
| 管理订单分页 | 禁止 | 所属影院，包含分页总数 | 全部 |
| 支付订单 | 本人订单 | 本人订单 | 本人订单 |
| 影厅、场次新增/修改/删除/状态调整 | 禁止 | 所属影院 | 全部 |
| 影院资料及状态修改 | 禁止 | 所属影院 | 全部 |
| 创建/删除影院、维护全局电影库 | 禁止 | 禁止 | 允许 |
| 排片分析、预测、模拟、草案校验和发布 | 禁止 | 所属影院 | 全部 |
| 保存/恢复/删除排片草稿 | 禁止 | 本人保存且仍属当前影院 | 本人保存 |
| 后台 Dashboard、票房、收入、场次统计 | 禁止 | 所属影院 | 全部 |
| 用户管理、影院分配、推荐算法评估 | 禁止 | 禁止 | 允许 |

退票时间、订单状态、是否已核销等业务规则对管理员同样生效。支付仍限订单本人，避免管理权限被用于花费他人积分或优惠券。普通用户知道他人的取票码也不能核销。

电影、影院详情、营业影厅和可售场次等购票目录保持公开；公开票房榜也保持公开。后台分页对影院管理员增加范围限制，公开目录不能作为修改、核销或查看订单的授权依据。

## 数据与后端校验

`V21__cinema_admin_scope.sql` 为 `user` 增加可空 `cinema_id`、索引及影院外键，一名影院管理员对应一家影院。既有账号不自动分配，缺失关联时返回 403，不能退化为全局查询。

JWT 验证成功后，每次请求从数据库加载当前账号状态、角色和影院。重新分配影院、降级或禁用账号后，旧令牌在下一次请求即受新权限限制。前端菜单只改善交互，授权以服务端为准。

`UserContext` 统一提供平台权限与影院范围校验。订单按场次的 `cinema_id` 判定归属；管理分页将影院条件下推 SQL，防止分页总数泄露。影厅和场次修改同时检查原归属和目标影院，阻止修改 `cinemaId` 搬移他人资源。排片草案、统计和核销采用相同边界。

## 升级与演示

1. 重启更新后的后端，等待 Flyway V21 成功执行；无需手工重建表或重置业务数据。
2. 平台管理员进入“用户管理 → 编辑”，设置角色为“影院管理员”，选择所属影院后保存。
3. 影院管理员重新登录以刷新界面账号信息，进入订单、影厅、场次或智能排片页面。
4. 在“订单管理”输入所属影院已支付订单的取票码，确认核销，列表显示核销状态和时间。
5. 平台管理员进入“推荐算法评估”，选择 K 并运行，保存 JSON 作为论文实验记录。有效样本不足时先补充历史行为与对应可售场次数据。

## 页面承诺调整

- 去掉“支持改签”“可改签”等承诺，保留在线选座、现有退票规则；支付页明确暂不支持改签。
- 隐藏未实现的通知、分享、购物车、组队等占位入口，保留实际可用的导航、订单和资料操作。
- 影院服务不再按影院 ID 生成；影厅类型来自真实影厅名称，价格来自实际场次，没有报价时不伪造起价。不再显示无来源的影院评分、停车等服务标签。
- 首页影院卡片显示真实名称、地址与坐标距离估算；影片详情去掉伪造的第三方评分和同好用户列表。
- 首页没有数据时不再保留可点击的演示电影；首页、影片列表和详情不再按影片 ID 编造起价、放映格式或推荐匹配分数。票价以实际场次为准，匹配分数只展示推荐接口返回值。
- 新增可用的推荐算法评估页面：完整混合模型、基线、消融、指标、评估协议、空样本/失败状态以及 JSON 导出。

## 安全回归

`CinemaAuthorizationTest` 覆盖本人/他人订单、跨影院详情/取消/退票/核销、未分配影院、影厅/场次双向归属检查、排片与经营统计。`ApiAuthorizationTest` 验证方法角色授权和数据库角色/账号状态对旧 JWT 的影响。

`LocalInfrastructureIT#cinemaPermissionsAreEnforcedThroughRealHttpSqlAndCurrentDatabaseAssignment` 在临时 MySQL 库和独立 Redis 中执行 Flyway、真实 HTTP 与 SQL。用两家影院的订单验证分页总数与搜索隔离、公共与管理接口边界、合法核销、重新分配、角色降级及禁用账号。测试不修改开发库。

管理端 `e2e/cinema-permissions.spec.ts` 使用 Chromium 和接口测试数据验证影院分配/降级提交、角色路由、核销失败与成功、评估 K 参数、导出、空样本和接口错误；接口真正的权限隔离由上述后端集成测试验证。

2026-09-27 验证结果：后端快速测试共 163 项，其中 158 项通过、5 项需显式开启的模型测试跳过；上述真实 MySQL/Redis 权限集成用例通过；管理端 5 项、用户端 14 项相关 Chromium 用例全部通过；两端生产构建通过。浏览器测试数据只用于验证交互，不作为推荐算法效果的论文实验数据。

可重复执行：

```powershell
cd movie-ticket-backend
.\mvnw.cmd test
$env:LOCAL_INFRA_TEST='1'
.\mvnw.cmd test-compile failsafe:integration-test failsafe:verify -Pintegration '-Dit.test=LocalInfrastructureIT#cinemaPermissionsAreEnforcedThroughRealHttpSqlAndCurrentDatabaseAssignment'
cd ../movie-ticket-admin
npm run build
npx playwright test e2e/cinema-permissions.spec.ts --workers=1
cd ../movie-ticket-user
npm run build
npx playwright test e2e/home.spec.ts e2e/movie-detail-media.spec.ts e2e/purchase-flow.spec.ts e2e/movies-profile.spec.ts --workers=1
```

集成测试需要本机测试 MySQL 可用，连接方式沿用 `LocalInfrastructureIT` 的环境配置；线上模型测试另需显式开启和模型凭据。

## uniCloud 对应实现

`movie-api/permissions.js` 统一校验影院范围、订单归属并生成统计和订单查询条件；`index.js` 每次读取数据库中的账号状态、角色与影院。`mts_user.cinemaId` 为可空关联字段，已有影院管理员不自动分配，未分配时返回 403。平台管理员在云端“用户管理”分配影院后生效。

云函数的 `test/cinema-permissions.test.js` 覆盖订单分页与总数、详情、取消/退票/核销、原/目标影院、统计、排片及草稿、账号分配和旧令牌角色变更，并验证场次超过单次查询上限时继续分页。与既有测试合计 25 项通过；两端云端生产构建通过。这些测试使用内存数据库替身，不能代替真实云数据库并发或事务验收。

云端推荐评估页明确展示“当前云端规则推荐”及评估局限：当前汇总数据可能包含后续信息，不是严格历史回放，也不是 Spring Boot 混合模型的实验结果。
