# 影票观 AI：连续观影规划

实现日期：2026-09-10。用户入口仍为 `/assistant`。

后续已增加聊天内确认下单与直接进入支付页，见 [影票观确认下单](ASSISTANT_CHECKOUT.md)；以下记录为观影规划阶段的实现与验证。

## 用户流程

1. 输入时间、人数、预算、排除题材或观影场景。
2. 展开聊天区上方的“本次观影条件”，查看当前条件，点击条件可移除；修改一项不会清除其余条件。
3. 助手统一查询场次、计算真实优惠后实付、检查连座，返回最多三项完整方案。
4. 点击“使用此观影方案”，将人数、优惠偏好和座位建议带入已有选座流程。选座页重新验证整组座位，最终下单、支付仍由用户确认。
5. “换成明天，其他条件不变”“选第二个”“不用积分，再算一下”可持续修改同一个计划。
6. “这些电影都看过了”排除上一批候选对应的影片。类型排除与影片排除在查询阶段执行。
7. 登录用户可点击“保存为长期排除偏好”，随后在同一面板查看或移除。长期排除项用于新对话，本次条件可覆盖它们；普通聊天更新只影响本次计划。

## 状态与接口

- `watchPlan.criteria`：日期、人数、影片/场次/影院、开场范围、结束上限、评分、时长、单票基础预算、优惠后总预算、用券/积分、连座要求、座位偏好、排除项及场景。
- `watchPlan.options`：与页面主要结果顺序对应的影片/场次引用，只保存真实引用和片名，不把旧报价、旧座位当成当前事实。
- 登录用户的计划保存到 `assistant_conversation.watch_plan`，每轮快照保存到 `assistant_turn.watch_plan`。读取上下文时，计划独立于最近五轮问答加载。
- 访客计划仅保留在页面内存，通过 `guestPlan` 随请求发送，服务端按白名单验证。登录请求忽略 `guestPlan`，不会采用客户端伪造的已保存历史。
- `POST /assistant/chat` 和 `/assistant/chat/stream` 支持可选 `planPatch`，供面板显式增量编辑；`null` 移除单项，空数组清除本次排除项。后端不接受其中的身份、金额结果、优惠券选择或订单操作。
- `GET /assistant/conversations/{id}` 增加当前 `watchPlan`；聊天完成响应增加 `watchPlan`。只有成功完成的回答更新会话计划；迟到请求不能覆盖较新的计划，删除会话后不会被迟到结果恢复。
- `GET /assistant/preferences`、`PUT /assistant/preferences`：当前登录账号的长期排除偏好。字段仅为 `excludedGenres`（最多10项）和 `excludedMovieIds`（最多50项），身份绑定JWT。

## 新工具及查询约束

| 工具 | 作用 |
| --- | --- |
| `update_watch_plan` | 增量保存本次意图、解析候选编号、排除上一批影片；不操作票、订单、券或积分 |
| `plan_movie_outing` | 读取已保存条件，统一筛选库存、优惠后预算、真实连座，输出完整观影方案 |
| `discover_movies` | 无需人数即可按题材、评分、时长、排除和场景筛选真实影片 |

`plan_movie_outing` 与 `discover_movies` 的模型参数为空对象，由后端注入当前计划，避免模型重新填写时遗漏条件。旧工具仍兼容；旧工具无法表达当前硬条件时，会要求使用组合查询。

组合方案从指定日期的全部合格场次计算优惠，不先按“总预算÷人数”限制原票价。与支付共用 `TicketPriceCalculator`，先计算用券、积分组合，再过滤 `maxTotal`。未登录时仅比较原价。

筛选支持 `endBefore`（当天结束时间上限，包含边界），和开场时间上限区别处理。人数为1至5人，多人默认连座；用户接受分散座位时可显式关闭连座要求。候选按照场景类型匹配（如有）、实付、积分消耗、开场时间排序，再逐项检查连座，直到找到所需数量或检查完候选。每个候选使用本地选座算法，不逐场调用外部模型。

无结果会分别说明：基础筛选交集无候选、优惠后超出总预算、预算内场次没有连座或复查时停售。不会将筛选交集为空归咎于某个未经验证的单一条件，也不会自动放宽预算或排除要求。

## 模型可靠性

- 动态追问由实际结果阶段生成：影片、场次、方案、订单、规则和空结果使用不同建议，不生成指向空候选的“第一个”。
- 明确的“不用积分”“保留优惠券”“换成明天”等修改由后端先应用，再主动查询，避免模型直接心算或复述旧报价。
- “只推荐一部”“请推荐两个方案”等明确数量限制由后端保护，最多三项；仅表达不用积分且没有观影条件时，不主动推荐无关影片。
- 本次条件有版本标记；模型更新条件却未按新条件查询时，后端补充真实查询结果再允许生成结论。
- 组合查询无候选或缺人数时，最终答复使用后端的真实诊断，避免模型把空结果说成找到方案。
- 仅保存意图和候选引用，价格与库存每次重新读取。所有工具结果保留来源，流式中间片段仍不直接显示。

## 场景能力边界

轻松、约会、家人同行、朋友聚会、独自观影为软偏好。当前场景排序依据片单中的真实类型；例如轻松场景优先类型包含喜剧或动画的候选。回答展示依据，不新增未经核实的适龄或敏感内容标签，也不把两个人推断为情侣。

场景排序目前使用可解释规则，结合模型的自然语言理解；没有引入新的训练模型、向量检索或影片内容评级数据。附近距离/路线及图片识别不在本次实现中。

## 启动和验证

重启后端，Flyway 自动执行 `V18__assistant_watch_plans.sql`，增加计划字段和长期排除表；不重建已有业务表。前端开发服务自动更新，发布版本需重新构建。

```powershell
cd movie-ticket-backend
.\mvnw.cmd test

cd ../movie-ticket-user
npm.cmd run build
npm.cmd run test:e2e -- assistant-planning.spec.ts assistant.spec.ts assistant-booking.spec.ts assistant-history.spec.ts price-comparison.spec.ts purchase-flow.spec.ts
```

可选真实模型五轮测试（使用现有模型配置，会调用付费模型；库存为合成数据，不修改业务数据）：

```powershell
cd movie-ticket-backend
$env:ASSISTANT_PLANNING_LIVE = '1'
.\mvnw.cmd '-Dtest=AssistantPlanningModelLiveTest' test
Remove-Item Env:ASSISTANT_PLANNING_LIVE
```

自动测试覆盖独立计划持久化、超过五轮后的恢复、身份隔离、访客输入校验、过期请求、明确禁用积分、真实优惠门槛、结束时间与排除SQL、没有连座后继续寻找、场景排序、空结果、前端参数传递及桌面/手机布局。真实模型测试独立验证五轮自然语言修改与候选指代；浏览器固定接口测试不冒充真实库存或支付联调。
