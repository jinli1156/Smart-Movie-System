# 混合推荐实验说明

## 行为权重

| 行为 | 基础权重 |
|---|---:|
| 浏览 | 1（单片最多累计 3 分） |
| 想看 | 3 |
| 已支付购票 | 5 |
| 五星评价 | 6 |

线上推荐的所有行为应用时间衰减 `max(0.35, 0.97^距参考时间天数)`，避免很久以前的兴趣长期主导推荐。离线评估的参考时间固定为每位用户的留出时间，而不是系统当前时间。

## 混合得分

候选影片总分由内容相似度 30%、用户显式偏好 15%、行为相似度 20%、场景因素 20%、热门趋势 15% 构成。

- 内容相似度：类型 35%、导演 20%、演员 20%、语言 15%、片长 10%。
- 场景因素：未来七天是否有可售场次、48 小时内场次、最低票价、用户与影院距离。
- 热门趋势：影片评分 70%、最近七天已支付订单销量 30%。
- 多样性：重排时同一主类型最多占推荐列表的 50%（至少允许 2 部），并对与已选影片过于相似的候选项施加 MMR 风格惩罚。

## 离线评估

管理员调用：

```http
GET /api/recommend/evaluation?k=6
```

评估采用严格按时间的 leave-one-out：留出每位用户最近一次“想看”作为测试正样本，并在该事件发生时间截断浏览、想看、已支付订单、评价和七日趋势数据。当前用户表中的显式类型偏好没有历史快照，因此评估时禁用，避免未来信息进入训练。

候选影片只取截至留出时间已经创建、且在留出时间后 7 天内存在非取消场次的影片，确保向历史用户推荐的是当时已知且真实可购买的内容。用户至少需要一次更早的想看行为；测试影片当时不可购买或历史证据不足的用户计入 `skippedUsers`，不进入指标分母。影片口碑也从留出时间前的评价重新聚合，不读取当前汇总评分。

- `Precision@K = 命中的测试正样本数 / (用户数 × K)`
- `Recall@K = 命中的测试正样本数 / 测试正样本总数`
- `NDCG@K = DCG@K / IDCG@K`，本项目每位用户一个正样本，因此越靠前命中得分越高
- `Coverage = 所有推荐结果涉及的不同影片数 / 可推荐影片总数`
- `Diversity`：列表内所有影片对的平均 `1 - 类型 Jaccard 相似度`

## 对照与消融实验

同一次接口调用会在完全一致的数据切分、候选集和 K 值下运行六个实验：

| 类别 | 实验 | 定义 |
|---|---|---|
| 完整模型 | `HYBRID` | 时间衰减 + 内容偏好 + 行为 + 场景 + 趋势 + 多样性重排 |
| 基线 | `POPULAR` | 只使用留出时间前七日销量和影片评分 |
| 基线 | `CONTENT` | 只用留出时间前的用户行为构建内容画像 |
| 消融 | `NO_DECAY` | 所有历史行为使用相同权重 |
| 消融 | `NO_SCENE` | 不使用未来场次、票价和距离特征 |
| 消融 | `NO_DIVERSITY` | 直接按相关性排序，不做类型占比限制和 MMR 重排 |

管理端 ADMIN 可在“推荐算法评估”页面切换 `K=3/5/6/10`，查看完整指标、基线对比、消融变化与评估协议。

入口为 `/recommendation-evaluation`，点击“运行评估”调用真实接口，点击“导出实验结果”保存带生成时间、有效/跳过用户数及完整协议的 JSON。有效用户为 0 时显示样本不足提示和指标占位符，不能据此宣称算法效果；请求失败时清空旧结果并允许重试。影院管理员无权进入此全平台实验页面。

论文实验应固定数据库快照、随机因素、K 值和候选时间窗，同时报告有效用户数与跳过用户数；用户数过少时指标不具有统计意义。离线指标用于模型间比较，不应直接称为线上点击率或购票转化率。

当前 `user_movie_behavior` 保存的是按“用户 × 影片 × 行为类型”聚合后的次数与最后发生时间，而不是逐事件日志。实现会完整排除最后发生时间晚于切分点的聚合记录，保证不读取未来，但无法恢复该记录在切分点前的部分浏览次数。若后续需要更精细的序列建模或显著性实验，建议新增只追加的行为事件表。
