# AI 辅助上架

本功能接入 Spring Boot 本地版及 `movie-ticket-admin`，入口为管理端 `/listing`。电影、影院、影厅管理页均提供快捷入口。独立的 uniCloud 工程尚未同步本功能。

## 使用流程

页面左上角可切换“模板导入”和“AI 导入”，两种方式分别保留当前页面中尚未提交的文字与文件。`/listing` 默认打开模板导入，`/listing?mode=ai` 可直接打开 AI 导入；刷新审核页、返回工作台时保留当前方式。

“模板导入”适合已整理的 Excel、CSV、JSON，字段直接映射，无需调用模型。“AI 导入”无需固定标题、字段顺序或文档排版，直接粘贴发行介绍，或上传 PDF、DOCX、TXT、MD、海报及普通 Excel 等原始资料，调用模型拆分并提取。AI 页面提供随上架类型变化的示例，示例标明为演示资料，实际导入时应替换为真实内容。

1. 选择电影、影院或影厅；影厅必须先选择所属影院。
2. 上传资料或粘贴文字，生成待审核草稿。一份文件可以包含多条同类型资料，每批最多 20 条，每条生成独立草稿。
3. 对照原始文字、图片和初次提取结果，补充缺失字段。可暂存后离开，或填写原因驳回。
4. 修改后先暂存以重新校验。勾选已核对资料，再点击“审核通过并发布”和“确认发布”。批量识别后可在“本次识别 N 条资料”中切换记录，发布一条不会发布其他条目；刷新后会恢复所属批次。

只有最后的发布操作会调用现有电影、影院、影厅创建服务，写入正式目录。电影默认发布为“即将上映”（2），管理员可改为“上映中”（1）或“下架”（0）；影院与影厅可选择启用或停用。影院管理员仅能操作所属影院的影厅资料；平台管理员可处理全部三类资料。

## 资料与模板

- 模板菜单仅保留批量 Excel（默认）、CSV、JSON，电影、影院、影厅分别提供模板，已移除单条模板入口及下载资源。
- Excel 批量模板每行一条资料，使用中文字段及黄色填写区，附填写说明。也可导入普通 Excel 表格，支持对应中文字段或英文属性名。日期单元格及整数、经纬度均保留实际数值；公式需转换成实际值再上传。
- CSV 使用一行表头和多行资料；JSON 支持单个对象、对象数组或 `{"records":[...]}`。多个结构化文件会合并为同一批次，最多 20 条。先解析完整批次，非法行或超限时返回错误，不会只导入第一条或保存半个批次。
- 支持 UTF-8 TXT、MD、JSON、CSV，以及可提取文字的 PDF、DOCX。PDF 限 30 页，扫描 PDF 请转成 JPG/PNG 图片后上传。
- JPG、JPEG、PNG 可作为原始图片资料；单条电影的第一张图片默认作为海报，单条影院的图片作为图片列表。批量资料中的图片作为共有原始资料保留，不会自动把一张图片分配给全部电影；需逐条核对图片归属。
- 每次最多 3 个文件，单个不超过 5MB，合计不超过 8MB，提取后的文字总计不超过 40000 字。
- JSON/CSV/Excel 在模板导入中直接拆分和映射字段，不调用语言模型。普通文字（含 PDF/DOCX 提取的文字）使用现有 DeepSeek，图片使用独立视觉模型，按条提取为 `records` 数组。AI 导入中的 Excel 按工作表保留原始文字、行列关系与数值，不要求固定表头；所有工作表合计最多 200 行、每行最多 30 列，同样不执行公式。
- `POST /listing/import` 的 `importMode` 支持 `TEMPLATE`、`AI`、`AUTO`。前端分别明确传入前两种；省略时使用 `AUTO` 兼容原有客户端。模板模式只接收 Excel／CSV／JSON 及对应文字内容，不会悄悄调用模型；AI 模式始终调用识别服务，不先套用模板规则。
- AI 模式下服务未配置或识别失败会返回明确错误，不创建空白草稿，当前页面保留原文和文件以便重试。兼容的 `AUTO` 模式仍可降级为一份原始资料草稿待人工补充，并明确提示无法确认拆分结果。请核对页面显示的识别数量。
- 影厅座位只有提供明确矩阵时才导入；也可在审核页显式点击“生成全可用规则座位”，再核对停用座位、过道等配置。生成规则座位不会自动发布。

## 配置与启动

文字提取复用现有 `assistant` 配置。视觉配置位于 `application.yml` 的 `listing`：

| 环境变量 | 用途 |
| --- | --- |
| `LISTING_VISION_API_KEY` | 视觉模型密钥，未设置时复用 `marketing.zhipu-api-key` |
| `LISTING_VISION_BASE_URL` | 默认 `https://open.bigmodel.cn/api/paas/v4` |
| `LISTING_VISION_MODEL` | 默认 `glm-4.6v-flash` |
| `LISTING_PROXY_URL` | 默认 `http://127.0.0.1:7890`；localhost、127.0.0.1、::1 直连 |

重新启动后端后，Flyway V28 创建 `listing_draft` 和 `listing_review_log`，V29 增加批次关联及索引；无需手工改表。已有运行实例需刷新 Maven 依赖并重新启动，以加载新接口和新增 PDF/Excel 依赖。

## 审核与一致性

- 服务器统一白名单过滤字段。模型和资料文件不能设置业务 ID、归属影院、评分或直接控制发布；归属影院来自管理员创建草稿时的选择，状态由审核页确认。
- 发布前检查必填字段、长度、日期、时长、坐标、媒体地址、图片列表及影厅座位布局。已存在的同名电影、同影院同名影厅、同名同址影院会被拦截。
- 草稿版本号防止旧页面覆盖新内容，数据库行锁及唯一发布标识防止并发重复创建。同一已发布草稿重复提交返回原目录编号。
- 文件解析和模型识别在数据库写入事务之外完成，批次内的全部草稿及生成记录在同一事务内保存。任意一条保存失败会回滚整个批次，不会留下部分草稿。
- 正式记录与发布状态在同一数据库事务内写入，失败时回滚。保存、驳回和发布均记录操作者、版本、时间及原因。已发布草稿只读，后续修改走原有管理页面。

## 验证

后端：`movie-ticket-backend/mvnw.cmd -Dtest=ListingWorkflowTest,ListingSourceReaderTest,ApiAuthorizationTest test`。

浏览器：在 `movie-ticket-admin` 执行 `npm run test:e2e -- e2e/listing.spec.ts --workers=2`。浏览器测试使用接口替身验证单条和批量流程、独立发布、批次恢复、宽窄屏和模板下载；后端测试使用隔离 H2、真实 MyBatis 与 Spring 事务验证 JSON 数组、多行 CSV/Excel、多个文件、五部影片测试文件、解析错误、批次回滚、图片归属和权限范围。不修改开发数据库，也不调用外部付费模型。
