# 200 用户、5 分钟混合业务压测报告

日期：2026-09-07。最终运行测试进程于 18:19:37 完成，测试通过。

## 结论

**在本机、小型测试数据、每次操作间隔 0.5–1.5 秒的条件下，系统通过 200 个活跃虚拟用户持续 5 分钟的混合业务压测。** 200 个用户均持续运行至结束，59,658 个 HTTP 请求全部成功，订单与库存一致性核对通过。

这可以支持“小规模试点具有基础承载能力”的判断，但不能据此承诺 200 人同时抢同一座位、无停顿请求、完整浏览器体验或生产大数据量下具有相同表现。

## 测试方式与限制

- 独立临时 MySQL 数据库，MySQL 9.0.1；独立 Redis 5.0.14.1；Spring Boot 随机 HTTP 端口。执行结束后已确认临时数据库清理。
- 200 个独立账号，8 个场次、每场 25 座，每个用户绑定不同座位。测试开始时仅有少量目录数据，订单在运行中增长。
- 使用项目 JWT 工具预建登录状态，所有 HTTP 请求通过真实鉴权；本次不包含登录密码验证的负载。
- 循环执行浏览→查座→下单→订单详情→支付退款，隔轮执行取消订单。用户每次操作间隔随机 500–1500 ms。
- 项目内部支付状态和退款逻辑真实执行，不涉及外部真实扣款或支付网关。
- 负载发生器和服务共用同一个 JVM、同一台机器，最大堆 768 MB；资源采样包含客户端和服务端，不能视为服务端独占指标。
- 本次未执行真实 AI 模型请求、静态资源下载、浏览器渲染、集中抢座、故障注入或超过 5 分钟的稳定性验证。此前同座竞争用例另有记录。

## 首轮说明

首轮也完成了 300 秒与 59,623 次成功请求，但报告核对 SQL 将真实字段 `seat_count` 错写为 `ticket_count`，导致测试工具在收尾阶段报错、未保存完整延迟统计。修正后增加了执行前 SQL 校验、核对前原始流量保存，并完整重跑。上方所有结果均来自最终成功运行，未混用两轮统计。
