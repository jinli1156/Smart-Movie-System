| 余票 / 座位 | 调用已有座位服务，返回布局、占用与余票快照；不锁座 |
| 智能选座联动 | 复用 SeatRecommendationService 推荐连座，点击卡片进入选座页预选；重新检查占用、布局、范围、人数和可售时间，整组失效则不预选；访客登录后保留方案 |
| 优惠试算 | 当前用户可用券与积分组合，展示原价、券抵扣、积分消耗和预计实付；复用支付计算器，不占券、不扣积分 |
| 订单查询 | 后端绑定当前登录身份，只返回自己的订单摘要，不返回取票码或用户资料 |

| RAG 知识库 | 检索项目购票、超时取消、退款、支付、推荐规则的关键词片段，将内容和来源交给模型；当前是本地词法检索，无向量数据库依赖 |
| Function Calling | 十四个白名单工具，其中一个仅更新本次观影条件，其他查询业务数据；服务端校验参数，最多6轮模型请求、12次工具执行 |
| 流式输出 | DeepSeek SSE → Spring SseEmitter → 浏览器 fetch；处理工具参数分片、UTF-8、异常和停止回答 |
| 语音助手 | 支持的浏览器可语音转文字，用户检查后发送；支持回答朗读和停止。识别能力、联网和麦克风权限依浏览器而定 |
| 图片理解 | 当前文本请求未启用。升级多模态时需实现图片校验、消息格式和模型能力开关，不能只改模型名就宣称支持 |

## 密钥与启动

模型默认 `deepseek-v4-flash`，地址 `https://api.deepseek.com`。可使用环境变量 `DEEPSEEK_API_KEY`、`AI_ASSISTANT_MODEL`、`AI_ASSISTANT_BASE_URL` 覆盖。协议参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 和 [工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)。

现有智能选座分析也复用这一配置，已同步切换为 DeepSeek 非思考模式请求；其候选座位仍由本项目算法生成。

本机密钥放在项目根目录 `.local/assistant.properties`：

```properties
DEEPSEEK_API_KEY=<你的密钥>
```

`.local/` 已被 Git 忽略。Spring Boot 从项目根目录或后端目录启动时自动加载该外置配置；该文件不位于 resources，不会打包进入 JAR。生产环境使用环境变量。不要把密钥放入 `VITE_*`、前端源码、可提交配置或日志。根目录 `.env.example` 仅作示例，不自动加载。

修改密钥、模型、系统提示词或知识库后重启后端。未配置密钥或上游故障时页面明确提示不可用，不伪装成本地模型回答。

```powershell
# 从项目根目录分别启动后端和用户端
cd movie-ticket-backend
.\mvnw.cmd spring-boot:run

# 另开终端，从项目根目录执行
cd movie-ticket-user
npm.cmd run dev
```

打开 `http://localhost:3000/assistant`。

## 可直接使用的系统提示词

完整 System Prompt 位于 [system-prompt.md](../movie-ticket-backend/src/main/resources/assistant/system-prompt.md)，后端直接加载此文件为第一条 `role: system` 消息，并追加本轮北京时间和登录状态。

函数定义位于 [tools.json](../movie-ticket-backend/src/main/resources/assistant/tools.json)，可作为 DeepSeek 请求的 `tools` 数组。仅复制提示词不能执行业务查询，宿主后端还必须执行 `tool_calls` 并把对应的 `tool_call_id` 和结果作为 `role: tool` 消息回传；本项目已在 `MovieAssistantService` 和 `AssistantToolService` 实现此循环。

```json
{
  "model": "deepseek-v4-flash",
  "thinking": { "type": "disabled" },
  "messages": [
    { "role": "system", "content": "将 system-prompt.md 的完整内容放在这里，并附本轮北京时间" },
    { "role": "user", "content": "今天有哪些可购票场次？" }
  ],
  "tools": ["此处替换为 tools.json 中的实际对象数组"],
  "stream": true
}
```

知识库位于 [knowledge.json](../movie-ticket-backend/src/main/resources/assistant/knowledge.json)。每个片段包含 id、标题、来源、关键词和正文。修改业务规则时同步更新片段。没有匹配的规则不补猜其他平台政策。

## 后端协议

| 接口 | 说明 |
| --- | --- |
| `GET /api/assistant/capabilities` | 返回模型名称、是否已配置及工具能力，不返回密钥；已配置不代表实时健康检查 |
| `POST /api/assistant/chat` | 兼容非流式调用，返回 Result 包装的 answer / suggestions / source / toolResults |
| `POST /api/assistant/chat/stream` | SSE；请求体同下方；登录用户携带现有 Bearer JWT |

```json
{"message":"帮我查今天的场次","history":[{"role":"user","content":"想看科幻片"},{"role":"assistant","content":"请告诉我片名或影院。"}]}
```

事件顺序：`status`（进度）、`delta`（新增文本）、`answer_reset`（清除中间查询轮的临时叙述）、`tool_result`（已执行查询）、`done`（最终完整结果）。工具调用可导致多组事件。最终回答只保留结论轮文本；中间查询默认折叠，主页结果卡片最多展示3条。`source=model` 表示正常完成，`unavailable` 表示未完成；最终以 `done.answer` 为准。无 `done` 的断流视为失败。最多6轮模型调用，最后一轮关闭工具调用，保留一次整理结论的机会。

查询结果 `ok=false` 时使用 `LOGIN_REQUIRED`、`INVALID_ARGUMENTS`、`QUERY_FAILED` 或 `QUERY_LIMIT`，不得当作空结果。列表默认每页8条，页码上限100，返回 total 与 page。排片支持 `limit`（1～8）、`maxPrice`（元）和 `priceExclusive`（严格小于上限；默认false）。例如「推荐一部40元以下电影」直接调用 `search_showtimes({"maxPrice":40,"priceExclusive":true,"limit":1})`，无需逐部查询推荐影片；「不超过40元」使用 false。过滤和价格排序在SQL分页前完成，`total=0` 时说明当前日期和条件无匹配，不擅自提高预算。推荐工具也支持 limit。结果卡片由真实工具结果构造站内链接，模型文本不执行 HTML。

流接口关闭代理缓冲和缓存；SSE 超时180秒，前端超时185秒，单次上游连接超时5秒、读取超时60秒。停止回答立即中止浏览器连接，后台在断连写入、读取超时或下一段上游数据时结束。后端最多同时处理4次对话请求，超额返回429。

## 隐私和操作边界

登录后的问题、回答、查询卡片和建议保存到数据库，刷新后恢复最近会话；支持历史列表、继续会话和删除。退出或换号清空当前页面展示，不删除原账号历史；访客对话仅保留在内存。浏览器不保存消息正文。请求携带的历史只能是 user / assistant，拒绝 system / tool 角色。身份在进入异步线程前取自 JWT，订单 SQL 始终附当前用户条件，管理员使用助手时也只能查自己的订单。模型和用户都不能指定 userId。

对话及回答所需的业务摘要会发送至配置的 DeepSeek 接口。工具结果不包含取票码、密码、用户手机号或支付凭据。模型工具可保存订单确认卡，不能锁座或创建购票订单；用户在聊天内明确确认后，专用接口创建待支付订单并进入支付页。支付、取消、退款和取票由用户操作。

## 选座联动、组合筛选和优惠试算（2026-09-05）

无需数据库迁移。后端新增服务、工具定义、提示词和知识库需要重启后端加载；用户端开发模式会热更新，生产环境需要重新构建。

### 演示问题

1. “找今天20点后、评分8分及以上、120分钟以内、IMAX厅、每张不超过50元的科幻电影，两个人看。”
2. 选定场次后：“两个人，想坐中间靠后，推荐连座。”点击“使用此座位方案”后，选座页重新读取布局及占用数据，预选仍可用的整组座位。
3. 选定场次和人数后：“帮我试算优惠，怎么付最便宜？”登录后展示最多三种方案。可继续要求“不使用积分”；也可针对自己的待支付订单进行试算。

### 接口与约束

- 选座与试算阶段继续使用 `/assistant/chat` 和 `/assistant/chat/stream`，`recommend_seats`、`quote_price` 仅查询；后续确认下单使用单独的 `/assistant/checkout` 接口，详见确认下单文档。
- `search_showtimes` 增加 `genre`、`minRating`、`maxDuration`、`startAfter`、`startBefore`、`hallKeyword`、`cinemaKeyword`、`people`。时间格式 HH:mm，区间含起点、不含终点；跨午夜分别查询两天。评分、时长均含边界。人数仅要求余票总数足够，连座需另外调用推荐工具。
- 当前没有独立的影厅制式字段，IMAX/杜比通过影厅名称关键词匹配，不能作为官方制式认证。影院地址关键词不是定位或距离筛选。
- `recommend_seats` 必须提供真实 `showtimeId` 和 1–5 人；复用已有算法及自然语言偏好分析，偏好是软匹配，不保证精确指定排号。返回最多3组，不锁座、不创建订单。URL中的座位方案仅为建议，不能替代提交订单的后端校验。
- `quote_price` 提供 `showtimeId + people` 或仅 `orderNo`，二选一；不接受金额、用户ID或优惠券ID。订单必须属于当前账号且待支付、未满10分钟。SSE线程使用控制器捕获的身份，不依赖异步线程内的登录上下文。
- 只查询未使用、已生效、未过期、达到门槛的个人优惠券，比较单券及不使用券方案；`usePoints=true`（默认）额外比较积分抵扣，false保留积分。金额取数据库，`TicketPriceCalculator` 同时被实际支付和试算调用。
- 最优按预计现金实付升序排列，同价优先少用积分，再优先不使用券。试算不保证券或积分在实际支付时仍可用；结果卡片只引导到选座/支付页面，用户重新确认。

### 回归覆盖

- 后端：组合条件SQL绑定、时间和评分边界、无匹配结果、伪造身份与参数拒绝；优惠门槛和有效期查询条件；券后积分计算、余额不足、超额抵扣、零实付；订单归属与超时；停售场次与空连座方案。
- 浏览器：同时展示座位方案和优惠明细；点击预选、失效座位整组拒绝、重复/越界/禁用座位拒绝；访客登录后返回方案；组合条件结果展示；原有助手多轮、异常、预算和移动端测试。
- 自动化浏览器用固定接口数据验证交互，不代表已对外部模型和真实支付渠道完成端到端验证。

本次验证：后端65项测试中63项通过、2项外部模型测试按默认配置跳过；16项助手浏览器用例通过，完整购票回归1项通过；用户端生产构建通过。完整购票回归发现并修复取票码弹窗首次打开未生成的问题，改为在弹窗打开完成后生成。


## 消息持久化（2026-09-05）

### 启用

重启后端，Flyway 自动执行 `V17__assistant_conversations.sql`，创建 `assistant_conversation` 与 `assistant_turn`；无需手动建表或重建数据库。刷新用户端即可。此前只存在页面内存、已经丢失的对话无法追溯恢复。

### 使用

- 登录后发送消息即创建会话并自动保存，刷新或重新登录后恢复最近会话。新对话保留旧记录，不等于删除。
- 顶部“历史会话”可切换、刷新和删除，删除需要在页面确认；列表每页20项。每次读取最近30轮，可加载更早消息。
- 查询卡片随回答保存，恢复后注明历史快照；票价、余票、优惠和订单状态必须重新查询。
- 问题在调用模型前保存；成功或中断回答在结束时保存，保存成功才发送 `done`。断连时后台会在检测到停止后保存已获得的内容；服务进程突然终止可能丢失未完成的回答，但问题仍保留。
- 未完成回答不进入模型上下文。同一会话同时只允许一条生成请求，4分钟租约避免进程异常后永久占用；下次发送时恢复过期任务。消息请求标识避免同一会话重复提交生成两份记录。
- 所有读取、继续、删除按后端登录身份限制；管理员也无法通过用户端读取他人的对话。生成期间删除会话，迟到回答不会恢复已删除记录。

### 协议

| 接口 | 内容 |
| --- | --- |
| GET `/assistant/conversations?page=1` | 当前用户会话列表 |
| GET `/assistant/conversations/{id}?before={turnId}` | 当前用户会话详情，before可省略 |
| DELETE `/assistant/conversations/{id}` | 删除会话及其消息 |
| POST `/assistant/chat/stream` | 增加可选conversationId与clientMessageId；登录新会话返回conversation事件；done包含conversationId |
| POST `/assistant/chat` | 同样自动持久化，响应包含conversationId |

服务端对持久化会话忽略浏览器history，改从数据库读取最近5轮完整成功对话，避免把伪造历史当作已保存内容。访客仍使用原有临时对话协议。

### 验证范围

`AssistantConversationServiceTest` 使用H2的MySQL兼容模式执行新增表结构与实际SQL，覆盖读写恢复、账号隔离、去重、任务恢复、级联删除、分页和上下文限制。浏览器历史测试使用固定接口数据，覆盖刷新恢复、继续会话、新建、删除、退出登录、未完成消息和移动端。测试不调用外部模型。

本次持久化验证结果：后端77项测试中75项通过、2项外部模型测试默认跳过；21项助手浏览器测试通过（含5项历史会话用例）；用户端生产构建通过。生产MySQL升级在下次后端启动时由Flyway执行，本次没有重建现有数据库。


## 动态推荐、观影画像与选座（2026-09-08）

- `/recommend/personal` 使用实时影片候选及浏览、想看、购票、评分加权偏好调用大模型，校验返回 ID、去重并补齐候选。推荐理由与 `analysisSource`、`model` 一并返回。模型故障时保留混合推荐排序。
- `/recommend/profile` 保留真实行为计数，并增加模型 `summary` 解读；首页和影片页直接展示，刷新画像或换一批会重新请求。雷达分数仍来自可复核的混合推荐计算，离线评估不调用模型。
- 智能选座的快捷偏好与自然语言输入均调用模型。模型只能排序算法产生的可用连座，返回前重新查询占用情况，剔除失效方案并补齐。前端只接收最新请求结果，应用方案后仍走原有锁座校验。
- 共用 `assistant` 的模型地址、模型名、密钥配置。结构化推荐使用 JSON 输出，读取超时上限 20 秒，前端请求超时 30 秒；异常或无有效候选时明确回退为算法来源。模型输入只包含影片和聚合观影偏好，不包含账号、电话及订单号。
- 真实模型验证：设置 `RECOMMENDATION_MODEL_LIVE=1` 后运行 `mvnw.cmd -Dtest=RecommendationModelLiveTest test`。使用现有环境变量/本地配置和合成观影数据执行三次真实调用，不写数据库。
