# AI 智能比价

电影详情页和待支付订单页提供「AI 智能比价」。页面自动从电影 ID 或所选场次识别电影；AI 小助手通过 `search_movies` 确认片名，再调用 `compare_prices` 返回真实比价卡片。

## 使用流程

1. 打开一部正在上映的电影，设置日期和 1–5 人，选择是否使用优惠券、积分。
2. 查看同片同日跨影院的原价、券抵扣、积分消耗和预计总实付；访客仅比较原价。
3. 点击「前往选座」，人数及优惠偏好沿选座、订单确认传入支付页。座位仍需用户确认。
4. 支付页支持手动调整优惠券与积分，从比价入口带入优惠偏好时按实际订单重新试算。当前订单优惠方案展示与一键应用按钮已移除，支付时仍由后端重新校验。
5. 用户确认支付后，原支付事务重新验证券归属、有效期、门槛、积分余额和订单状态，再核销优惠券与积分。比价查询本身无资产变更。

助手示例：「帮我比价《流浪地球2》，明天，两个人，使用优惠券但保留积分，推荐最省钱的场次。」自然语言助手需要现有 DeepSeek 配置；页面比价直接调用后端计算，无需模型密钥。

## 计算与范围

- 数据源仅为本系统排片、影院、影厅及当前账号资产，尚未接入猫眼、淘票票等外部平台，不声称全网最低价。
- 支持北京时间今天起 90 天内的单日查询；场次须可售、电影上映、影院及影厅营业、实体未删除、开场至少剩 15 分钟、余票满足人数。
- 先获取当日全部合格场次，再按每场「单价 × 人数」判断券门槛，比较不用券、单券、积分及券加积分的方案。不按原票价截断候选。
- 与支付共用 `TicketPriceCalculator`：每单最多一张券，先扣券，再按 100 积分抵 1 元，每单积分最多抵 1 元，不超过余额和剩余应付，支持一位小数积分。
- 按总实付升序，同价优先少消耗积分，再优先较早开场、较小场次 ID。单场次优惠同价时优先不用券，券之间优先较早到期及较小 ID。
- 返回前 10 个结果，同时给出实际比较数、预算内匹配数和查询时间。最低实付指当前最低现金支出，不代表积分没有价值。
- `maxTotal` 为全部人数优惠后的总预算，应用于优惠计算之后。页面目前提供日期、人数、用券、积分筛选；总预算可通过助手或接口指定。
- 余票为快照且不保证连座。查看其他场次不取消旧订单，不保留优惠，不锁座；价格及资产在支付时重新校验。

## 接口

`GET /api/pricing/compare`

参数：`movieId` 或 `showtimeId`（二选一），`date`（YYYY-MM-DD，可省略），`people`（默认 1），`useCoupons`、`usePoints`（默认 true），`maxTotal`（可选）。从场次进入且省略日期时，自动使用该场次日期；只提供电影时默认今天。

返回：`movieId`、`movieTitle`、`date`、`people`、`personalized`、`availablePoints`、`comparedCount`、`matchedCount`、`queriedAt`、`offers`、`notice`。每个 offer 含真实场次/影院/影厅、开场时间、余票、原价和 `bestPlan` 优惠明细。

`GET /api/pricing/orders/{orderNo}/quote?usePoints=true`

仅登录用户本人未超时待支付订单可试算，返回原价、积分余额、最优方案及备选方案。身份来源为服务端认证上下文，接口不信任客户端传入的用户 ID、金额。两个查询均设置 `Cache-Control: no-store`。

## 验证

后端 `PriceComparisonTest` 覆盖用券门槛改变场次排序、优惠后预算、保留资产、访客隔离、场次识别、全量排序再截断和无结果。`PriceComparisonQueryTest` 使用 H2 执行实际 mapper SQL，验证日期、15 分钟截止、余票及各实体状态/删除过滤。`ApiAuthorizationTest` 覆盖新接口身份与参数边界。原优惠试算、支付并发及购票 API 测试继续作为回归验证。

用户端 `e2e/price-comparison.spec.ts` 使用模拟 API 验证详情识别、筛选刷新、选座偏好、访客/失败/空状态、支付参数和手机布局；不能替代生产数据库和模型服务的联调验收。
