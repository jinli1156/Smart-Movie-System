# 第三阶段测试指南

本文档提供第三阶段核心购票流程的完整测试步骤。

## 前置准备

### 1. 确保服务已启动

```bash
# 后端
cd movie-ticket-backend
mvn spring-boot:run

# 用户端前端
cd movie-ticket-user
npm install
npm run dev

# 管理端前端（可选）
cd movie-ticket-admin
npm install
npm run dev
```

### 2. 准备测试数据

需要在数据库中准备：
- 至少1个影院
- 至少1个影厅
- 至少1部电影
- 至少1个场次

可以通过管理端或API创建测试数据。

## 完整购票流程测试

### 步骤1：访问首页

1. 打开浏览器访问 http://localhost:3000
2. 应该看到首页，显示"正在热映"的电影列表
3. 点击"即将上映"标签，切换到即将上映的电影

**预期结果：**
- ✅ 页面正常加载
- ✅ 电影卡片正确显示
- ✅ 海报、标题、评分、类型等信息完整
- ✅ 标签切换正常

### 步骤2：查看电影详情

1. 点击任意电影卡片
2. 进入电影详情页

**预期结果：**
- ✅ 电影详细信息正确显示
- ✅ 海报、评分、导演、演员、简介等信息完整
- ✅ 影院选择下拉框正常
- ✅ 日期选择器正常

### 步骤3：选择影院和场次

1. 在影院下拉框中选择一个影院
2. 选择日期（默认今天）
3. 查看场次列表

**预期结果：**
- ✅ 场次列表正确加载
- ✅ 显示时间、影厅、价格、剩余座位
- ✅ 场次卡片可点击

### 步骤4：登录（如未登录）

1. 点击场次卡片
2. 如果未登录，会跳转到登录页
3. 输入用户名和密码登录

**测试账号：**
- 用户名：`user`
- 密码：`user123`

**预期结果：**
- ✅ 未登录时正确跳转到登录页
- ✅ 登录成功后返回场次选择
- ✅ 登录后可以继续购票流程

### 步骤5：选择座位

1. 登录后自动进入座位选择页
2. 查看座位图
3. 点击Canvas上的座位进行选择

**操作测试：**
- 点击绿色座位（可选）→ 变为蓝色（已选）
- 再次点击蓝色座位 → 取消选择，变回绿色
- 点击灰色座位（已占用）→ 提示"该座位已被占用"
- 选择超过5个座位 → 提示"最多只能选择5个座位"

**预期结果：**
- ✅ 座位图正确绘制
- ✅ 银幕位置标识清晰
- ✅ 座位状态颜色正确
  - 绿色：可选
  - 蓝色：已选
  - 灰色：已占用
- ✅ 点击选座交互正常
- ✅ 已选座位标签正确显示
- ✅ 总价实时计算正确

### 步骤6：确认订单

1. 选择1-5个座位
2. 点击"确认选座"按钮
3. 进入订单确认页

**预期结果：**
- ✅ 观影信息正确显示
- ✅ 座位信息正确显示
- ✅ 可以填写备注
- ✅ 总价计算正确

### 步骤7：提交订单

1. 填写备注（可选）
2. 点击"提交订单"按钮
3. 等待订单创建

**预期结果：**
- ✅ 订单创建成功
- ✅ 跳转到支付页面
- ✅ 显示订单号
- ✅ 显示完整订单信息

### 步骤8：支付订单

1. 在支付页面查看订单信息
2. 点击"立即支付"按钮
3. 确认支付

**预期结果：**
- ✅ 支付确认对话框弹出
- ✅ 支付成功提示
- ✅ 跳转到订单详情页
- ✅ 订单状态更新为"已支付"

### 步骤9：查看订单

1. 点击顶部"我的订单"
2. 查看订单列表
3. 点击订单查看详情

**预期结果：**
- ✅ 订单列表正确显示
- ✅ 可以按状态筛选
- ✅ 订单信息完整
- ✅ 订单详情页正确显示

## 座位锁定测试

### 测试场景：两个用户同时选座

**步骤：**
1. 打开两个浏览器窗口（或使用隐身模式）
2. 两个窗口都登录不同的账号
3. 都进入同一场次的座位选择页
4. 用户A选择座位"1排1座"并提交订单
5. 用户B尝试选择同一座位

**预期结果：**
- ✅ 用户A成功创建订单
- ✅ 用户B刷新页面后，该座位显示为灰色（已占用）
- ✅ 用户B无法选择该座位
- ✅ 点击该座位提示"该座位已被占用"

## 订单取消测试

### 测试场景：取消待支付订单

**步骤：**
1. 创建一个订单但不支付
2. 在订单列表中找到该订单
3. 点击"取消订单"按钮
4. 确认取消
5. 返回座位选择页查看

**预期结果：**
- ✅ 订单状态更新为"已取消"
- ✅ 座位重新变为可选状态
- ✅ 场次可用座位数增加
- ✅ Redis锁被释放

### 测试场景：尝试取消已支付订单

**步骤：**
1. 找到一个已支付的订单
2. 查看订单详情

**预期结果：**
- ✅ 没有"取消订单"按钮
- ✅ 无法取消已支付订单

## API接口测试

### 1. 创建订单

```bash
# 先登录获取token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"user","password":"user123"}'

# 创建订单
curl -X POST http://localhost:8080/api/order \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {token}" \
  -d '{
    "showtimeId": 1,
    "seats": ["1排1座", "1排2座"],
    "remark": "测试订单"
  }'
```

**预期返回：**
```json
{
  "code": 200,
  "message": "订单创建成功",
  "data": "ORDER1715875200001234"
}
```

### 2. 查询我的订单

```bash
curl -X GET "http://localhost:8080/api/order/my?page=1&size=10" \
  -H "Authorization: Bearer {token}"
```

**预期返回：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [...],
    "total": 10,
    "size": 10,
    "current": 1,
    "pages": 1
  }
}
```

### 3. 获取座位状态

```bash
curl -X GET http://localhost:8080/api/showtime/1/seats
```

**预期返回：**
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "totalRows": 10,
    "totalCols": 15,
    "seatLayout": "{}",
    "occupiedSeats": ["1排1座", "1排2座"],
    "availableSeats": 148,
    "totalSeats": 150
  }
}
```

### 4. 支付订单

```bash
curl -X POST http://localhost:8080/api/order/ORDER1715875200001234/pay \
  -H "Authorization: Bearer {token}"
```

**预期返回：**
```json
{
  "code": 200,
  "message": "支付成功",
  "data": null
}
```

### 5. 取消订单

```bash
curl -X POST http://localhost:8080/api/order/ORDER1715875200001234/cancel \
  -H "Authorization: Bearer {token}"
```

**预期返回：**
```json
{
  "code": 200,
  "message": "订单已取消",
  "data": null
}
```

## 常见问题

### 1. 座位图不显示
- 检查Canvas是否正确渲染
- 检查座位数据是否正确返回
- 查看浏览器控制台错误

### 2. 订单创建失败
- 检查用户是否登录
- 检查座位是否已被占用
- 检查场次是否有效
- 查看后端日志

### 3. 支付失败
- 检查订单状态
- 检查用户权限
- 查看后端日志

### 4. 座位锁定失败
- 检查Redis是否启动
- 检查Redis连接配置
- 查看Redis日志
